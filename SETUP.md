# Установка

Для нейронки. Человек говорит «настрой по SETUP.md» — ты проходишь шаги сам. Человека просишь только о том, что может сделать только он: такие места помечены **Человек:**.

## 1. Окружение

Нужны Python 3.10+ и git. Считай, что машина пустая: сначала проверь `python3 --version` (Windows: `py --version`) и `git --version`. Чего нет — ставь сам, человека зови только там, где помечено **Человек:**.

- **macOS:** `xcode-select --install` — даст и git, и python3. **Человек:** нажать «Установить» в появившемся окне, ждать до 10 минут. Если есть Homebrew — быстрее: `brew install python git`.
- **Windows:** работай в PowerShell. `winget install -e --id Python.Python.3.12` и `winget install -e --id Git.Git`. **Человек:** подтвердить окна установщика. После установки открыть новый терминал, иначе команды не найдутся. Активация окружения: `.venv\Scripts\activate`.
- **Linux / WSL:** `sudo apt update && sudo apt install -y python3 python3-venv python3-pip git`. **Человек:** ввести пароль sudo.

Дальше: `python3 -m venv .venv` (Windows: `py -m venv .venv`), активировать, `pip install -r automation/requirements.txt`. Проверка: `python automation/tg_export.py --help` печатает подсказку. Не печатает — читай ошибку и чини, человеку не отдавай.

GitHub CLI (`gh`) понадобится только в шаге 6, там и ставится.

## 2. Ключи Telegram

Скопируй `.env.example` в `.env`. Ключи получает **человек**, продиктуй ему по шагам:

1. Открой https://my.telegram.org. Номер в международном формате (`+7…`), Next.
2. Код придёт сообщением в сам Telegram, не по SMS. Введи, Sign In.
3. Нажми API development tools.
4. App title и Short name — любые латиницей (например `status`), Platform — Desktop, остальное пусто. Create application.
5. Пришли мне `api_id` (число) и `api_hash` (строка из букв и цифр).

Запиши в `.env`. Больше никуда. Ключи не подошли — чаще всего лишний пробел или кавычка.

## 3. Вход в Telegram

Вход делает **человек** в своём терминале — у тебя нет экрана для QR и ввода пароля. Дай ему команду и жди, пока скажет «вошёл»:

```
source .venv/bin/activate && python automation/tg_export.py --list
```

Появится QR. Человеку: «Telegram на телефоне → Настройки → Устройства → Подключить устройство → наведи камеру на QR». Стоит облачный пароль — скрипт спросит, человек вводит сам; ты пароль не запрашиваешь и не сохраняешь. Вошёл — скрипт печатает список чатов; дальше выгрузку запускаешь уже ты. Сессия — `telegram_session.session` в корне; отозвать: Telegram → Настройки → Устройства.

Не сработало: код не пришёл — выключить VPN на телефоне; QR протух — скрипт покажет новый; чат не находится — взять точное название из `--list`.

## 5. Первый проект

`cp -r projects/_template projects/<имя>`. Заполни `projects/<имя>/README.md` — название, клиент, что делаем. Выгрузи чат: `python automation/tg_export.py "<часть названия>" --project <имя>` — последние 14 дней; глубже — `--days 60`, быстрее — `--days 7`. Ограничение только по дням, не по числу сообщений: тогда понятно, какой период покрыт целиком. Повторный запуск дописывает новые сообщения в тот же файл. Тема форума: `--topics`, потом `--topic "<название>"`. Скажи человеку: файл, сколько сообщений, период.

Есть выгрузка чата или другие материалы — положи в `projects/<имя>/sources/`.

Дальше — по скиллу `project-status`.

## 6. Своя копия в закрытом репозитории

Когда папка собрана — чтобы команда видела то же и нейронка у каждого читала одну папку.

Делается по скиллу `github`. Порядок: `git remote remove origin` (клон смотрит на открытый набор автора — туда пушить нельзя) → `git config user.name` и `user.email`, пустые — спросить человека и выставить → проверка `python automation/publish_check.py` → исправить всё `✗` → коммит → `gh repo create <имя> --private --source=. --push`. Нет `gh` — поставить: macOS `brew install gh`, Windows `winget install -e --id GitHub.cli`, Linux/WSL `sudo apt install -y gh`. `gh auth status` не проходит — **Человек:** «сейчас откроется браузер, войди в GitHub»; `gh auth login --web`.

Сразу после первой публикации — проверить, что репозиторий закрыт: `gh repo view --json isPrivate` должен дать `true`, и **человек** сам открывает страницу репозитория в браузере и видит метку Private. Открытый — закрыть: `gh repo edit --visibility private --accept-visibility-change-consequences`.

Дальше: перед работой `git pull`, после — публикация тем же скиллом; правка коллеги — факт со своим источником в журнал. Доступ коллеге: Settings → Collaborators.

## 7. Обновление без рук (после воркшопа, по желанию)

Схема, которая работает у автора: сервер, на котором залогинен Claude Code по подписке, и таймер (systemd или cron) раз в ночь. Прогон: `git pull --ff-only` → `tg_export.py "<чат>" --days 2 --project <имя>` по каждому проекту → `claude --print "по скиллу project-status обнови проект <имя>"` → `python automation/publish_check.py` → коммит и push. Ошибка на любом шаге — прогон останавливается, ничего не публикуется.

Чего не обойти, проверено на себе:
- Окно выгрузки — с потолком (`--days 2`, не «всё с прошлого раза»): без потолка один сбой съедает лимиты подписки на несколько часов.
- Тихий день — пропускать: нет новых сообщений, нейронку не звать.
- Логин Claude Code на сервере живёт около месяца — перелогин по календарю, иначе ночные прогоны молча падают.
- Фильтр секретов и проверка перед публикацией — те же, что руками. Ночной прогон не получает права их пропускать.

Собрать это под свой сервер — задача для нейронки: «сделай ночное обновление по разделу 7 SETUP.md».
