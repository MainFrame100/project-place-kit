# automation — скрипты

Всё повторяемое — здесь. Новый скрипт — строка в этой таблице.

| Скрипт | Что делает | Запуск |
|---|---|---|
| `redact.py` | скрывает пароли, ключи, токены в текстах: слова-подсказки по-русски и по-английски с опечатками + форматы ключей. Значение → `[скрыто: пароль]`, контекст остаётся | `python automation/redact.py --check .` — проверить перед коммитом; `python automation/redact.py <путь>` — вычистить на месте |
| `publish_check.py` | проверка перед публикацией: секреты, секретные файлы в git, `.gitignore`, README в папках, файлы в корне, скрипты вне automation/, правки сырья, удаления в журнале, дата статуса, закрыт ли репозиторий на GitHub. Код выхода 1 — публиковать нельзя | `python automation/publish_check.py` — вызывает скилл `github` |
| `tg_export.py` | выгрузка Telegram в `projects/<имя>/sources/`: личка, группы, каналы, темы форумов. Вход по QR, облачный пароль спрашивает сам. Пароли в сообщениях скрывает через `redact.py` | `python automation/tg_export.py "<часть названия>" --project <имя>` — последние 14 дней; `--days 60` — глубже; `--list` — чаты; `--topics` / `--topic` — темы форума. Повторный запуск дописывает новые сообщения в тот же файл |

Ключи — `.env` в корне (см. `.env.example`), сессия — `telegram_session.session` в корне. Зависимости — `requirements.txt`.

Тесты фильтра: `cd automation && python -m pytest test_redact.py -q`.

Выход `tg_export.py`: `telegram-<чат>.md` (по дням: время, автор, `#номер` сообщения, текст) и `.json`. Номер сообщения — это и есть ссылка для якоря.
