# project-status — сырьё → журнал → документы → проверка

Работа идёт в `projects/<имя>/`. Правила фактов — в `CLAUDE.md`, здесь — порядок. Сбор, синтез и проверка — три разных прохода, не смешивать: кто собирает факты, тот не трактует.

## 1. Сырьё → журнал

Прочитай всё в `sources/`: выгрузки чатов, документы человека, `links.md`. Ссылка без содержимого — строка в карту материалов с `[GAP]`, в журнал не идёт. Разложи события по дням в `journal/` в формате и с шагом файла (месяц / неделя / день) из `journal/README.md`.

В журнал: изменился статус обязательства · появился или снят блокер · принято решение · кто-то пообещал · вопрос без ответа · риск. Не в журнал: «поговорили о», «обсудили в целом».

В конце — отчёт покрытия человеку в чат: какие источники прочитал, период, сколько сообщений, сколько стали фактами. Пустой источник — тоже строка, с 0 и `[GAP]`. В файлы отчёт не пишется. На этом шаг закончен: проверка (раздел 3) идёт после документов, здесь её не запускать.

## 2. Журнал → три документа

Каждое утверждение — со ссылкой на запись журнала или файл в `sources/`.

**`passport.md`** — клиент и его бизнес; что делаем и что клиент ждёт на выходе; деньги и сроки; команда с обеих сторон и роли; где общаемся; постоянные правила проекта.

**`status.md`** — шапка `Обновлено: YYYY-MM-DD`. (1) Ситуация на сегодня, 5–10 строк: «прочитал — понял, где проект и что делать на неделе». (2) Обязательства — каждое со статусом «отчитались / проверили / клиент принял» и датой. (3) Блокеры — у каждого «чей мяч» и «висит с». (4) Открытые вопросы. (5) `[GAP]`-лист — что не удалось выяснить. Пересобирается целиком; история — в журнале.

**`materials.md`** — таблица: ссылка | что это | откуда известно (#сообщение) | дата. Только упомянутое в источниках.

## 3. Проверка

Без проверки статус не считается готовым. Когда человек ведёт по шагам («разложи», «собери», «проверь») — запускать по его команде «проверь», а после сборки документов предложить её одной строкой. Без человека (обновление по расписанию) — всегда, сразу после документов.

Проверяльщик и скептик — отдельные субагенты старшей моделью (правило «Агенты и модели» в `CLAUDE.md`). Нет субагентов — каждый из них отдельным запросом с чистого листа после того, как статус записан в файл.

1. **Проверяльщик.** По каждому обязательству и блокеру статуса открыть источник: цитата дословна? автор тот? дата та? вывод не шире цитаты? Итог: подтверждено / с оговоркой / не подтвердилось. Утверждений больше 15 — сначала обязательства и блокеры, остальные пометить «не проверено».
2. **Скептик.** По каждому ключевому выводу: «если это неверно, что должно быть в источниках?» — найти. Вердикт: устоял / ослаб / опровергнут.
3. **Человек.** Покажи 3 факта с якорями для сверки руками. Спроси: «что ты знаешь такого, чего нет в данных?». Его правка — запись в журнал «со слов …, дата». Старое не затирается.

Ищи у себя: пересказ вместо ссылки · вывод шире цитаты · «отчитался» записано как «сделано» · нет `[GAP]` · один случай стал «системной проблемой».

## Ответы на вопросы

- «Что по проекту?» — `status.md` + журнал, каждое утверждение со ссылкой.
- «Где лежит X?» — `materials.md`, отдать ссылку, не пересказ.
- «Какие решения приняты?» — журнал, записи типа «решение».
- Нет в материалах — «в материалах нет», показать `[GAP]`.

## Обновление

Только новое с даты `Обновлено`. Журнал дописать, статус пересобрать, паспорт — если изменилось жёсткое.
